# Работа оператора поддержки

Это руководство рассчитано на человека, который впервые открыл поддержку в Retenive. Здесь нет технического устройства системы. Только ежедневная работа: найти обращение, понять ситуацию, ответить и не потерять контекст.

Интерфейс зависит от ваших прав в выбранном проекте. Если раздела или кнопки нет, сначала уточните доступ у лида. Не пытайтесь открыть чужую ссылку из другого проекта.

## Начало смены: короткий маршрут

1. Проверьте проект в левом верхнем углу. Все очереди, шаблоны и настройки относятся только к нему.
2. Откройте `Поддержка`.
3. Нажмите `Моя доступность` и выберите честное состояние.
4. Посмотрите новые обращения, задачи без назначения и элементы с риском SLA.
5. Возьмите одно обращение, прочитайте переписку и контекст справа.
6. Ответьте, оставьте внутреннюю заметку или передайте работу.
7. Перед уходом завершите активные обращения или передайте их следующей смене.

> Не начинайте с ответа. Сначала проверьте проект, назначение, последнее сообщение и срок SLA.

## Как устроено рабочее место

На большом экране рабочее место разделено на три области.

| Область | Что находится внутри | Для чего нужна |
| --- | --- | --- |
| Слева | Представления, поиск и список входящих | Найти следующую работу |
| По центру | Переписка или сводка обращения | Понять, что произошло, и ответить |
| Справа | Обращение, пользователь, профиль, SLA, назначение и другие вкладки | Проверить контекст перед действием |

На телефоне эти области открываются по очереди. Кнопка `Назад` возвращает к списку, а `Контекст` открывает сведения об обращении. Это тот же рабочий процесс, только без трёх колонок одновременно.

## Обращение и чат — не одно и то же

Обращение, или Case, хранит рабочий статус: тему, приоритет, классификацию, назначение, SLA и историю решений.

Чат хранит сообщения. У обращения может быть один связанный чат, а может не быть ни одного. В таком случае вы всё равно можете открыть обращение, изменить доступные рабочие поля и изучить историю, но ответить пользователю в переписке нельзя.

Переключатель `Обращения / Все чаты` меняет тип списка. Он не преобразует обращение в чат и не создаёт новую переписку.

## Как выбрать следующую работу

Начните с системных представлений. Они показывают, например, ваши обращения, неназначенные команды или все доступные элементы. Сохранённое представление — это ваш набор фильтров с понятным названием.

В строке списка обращайте внимание на четыре вещи:

- кто назначен;
- есть ли непрочитанные сообщения;
- какой приоритет установлен;
- сколько времени осталось по SLA.

Поиск нужен для конкретной задачи: найти обращение, чат или пользователя. Фильтры сужают очередь по статусу, теме, каналу, назначению и другим доступным признакам. После проверки очистите лишние фильтры, иначе следующая смена может показаться пустой.

Из разделов `Пользователи` и `Сейчас онлайн` можно открыть поддержку уже с выбранным человеком. В таком режиме список ограничен его чатами. Поиск и сохранённые представления временно недоступны, чтобы в список не попали чужие обращения. Вернитесь в обычную поддержку, когда закончите работу с этим пользователем.

## Назначение, работа и наблюдатели

Эти состояния похожи, но отвечают на разные вопросы.

| Термин | Простой вопрос |
| --- | --- |
| Назначение | Какая команда или оператор отвечает за обращение? |
| Взял в работу | Кто сейчас ведёт активную работу? |
| Наблюдатели | Кто следит за изменениями, но не становится владельцем? |
| Доступность | Может ли оператор получить новую работу? |

`Взять в работу` назначает разрешённую вам ответственность. `Передать` открывает выбор команды или сотрудника. `Снять` убирает текущее назначение, если это разрешено правилами проекта.

При конфликте версия обращения уже изменилась у другого сотрудника. Не повторяйте действие вслепую. Перечитайте данные, проверьте нового владельца и подтвердите решение ещё раз.

## Доступность и предложения работы

Доступность сообщает системе, готовы ли вы получить новую работу.

- `Доступен` — можно предлагать новые обращения.
- `Занят` — новая работа временно не нужна.
- `Отошёл` — вы недоступны на короткое время.
- `Завершаю` — новые задачи не нужны, текущие ещё закрываются.
- `Офлайн` — смена закончена.

Предложение работы появляется на ограниченное время. Примите его, только если готовы заняться обращением сейчас. Отклонение не закрывает обращение: система продолжит подбор по правилам очереди.

## Что проверить перед ответом

Прочитайте последние сообщения и посмотрите, где стоит разделитель новых сообщений. Затем проверьте:

- язык пользователя и режим перевода;
- кто отвечает за обращение;
- приоритет и срок SLA;
- внутренние заметки;
- классификацию и текущий статус;
- предупреждения о доставке или внешней задаче.

Присутствие других операторов показывает, кто сейчас смотрит этот чат. Просмотр не означает назначение. Если в переписке уже работает коллега, договоритесь, кто отвечает.

## Вкладки контекста

Набор вкладок зависит от прав и выбранного элемента.

| Вкладка | Что в ней искать |
| --- | --- |
| Обращение | Статус, классификацию, приоритет, SLA, назначение и маршрутизацию |
| Пользователь | Безопасную сводку по человеку и текущему диалогу |
| Профиль | Разрешённые поля продукта, источник и свежесть данных |
| Материалы | Внутреннюю базу знаний и доступный рабочий контент |
| Интеграции | Связанные задачи во внешних системах |
| События | Подтверждённые факты из истории пользователя, если доступ разрешён |

Не переносите сведения из закрытой вкладки в публичный ответ автоматически. Сначала проверьте, можно ли сообщать их пользователю.

## Как ответить и не потерять черновик

Внизу переписки есть два режима: публичный ответ и внутренняя заметка. Публичный ответ увидит пользователь. Внутренняя заметка остаётся внутри команды.

Черновики хранятся отдельно для каждого чата и каждого режима. Текст публичного ответа не переносится во внутреннюю заметку. При смене проекта или потере доступа защищённый черновик очищается.

Перед отправкой:

1. Проверьте режим.
2. Перечитайте текст и подставленные данные.
3. Прикрепите нужные файлы.
4. Убедитесь, что перевод соответствует исходному смыслу.
5. Нажмите `Отправить` или `Добавить заметку` один раз.

Если результат неизвестен из-за сети, используйте предложенную проверку или повтор той же попытки. Новое сообщение с новым нажатием может создать дубль.

## Перевод и язык

`Оригинал` показывает исходный текст. `Перевод` показывает подтверждённую переведённую версию. Язык интерфейса, язык входящего сообщения и язык вашего ответа могут отличаться.

Если вы изменили исходный ответ, старый предварительный перевод больше не считается актуальным. Получите новый перевод и перечитайте его. Отправка без перевода требует явной причины, если проект разрешает такой обход.

Не исправляйте содержание сообщения только ради красивого перевода. Если смысл исходника неверен, сначала исправьте исходный текст.

## Шаблоны ответов и внутренняя база знаний

`Шаблоны` вставляют подготовленный ответ в поле ввода. Шаблон не отправляется сам: его можно и нужно проверить, дополнить и сократить под ситуацию.

Шаблон может быть доступен только для определённой темы, языка или команды. Переменные подставляются только из разрешённых данных. Если значения нет, вы увидите запасной текст или предупреждение.

Внутренняя база знаний помогает найти инструкцию для сотрудника. Её материалы не отправляются пользователю автоматически. Сначала прочитайте документ, затем сформулируйте ответ своими словами или по утверждённому шаблону.

## Вложения и состояние сообщения

Добавленные файлы сначала загружаются. Не отправляйте ответ, пока нужное вложение не готово. Ошибочный файл удалите до отправки.

После принятия сообщения состояние меняется по мере доставки: принято, отправлено, доставлено, прочитано или ошибка. `Принято` ещё не означает, что пользователь получил сообщение.

При ошибке посмотрите безопасное пояснение в интерфейсе. Не создавайте второй ответ, пока система предлагает проверить исходную попытку.

## Статус, классификация и эскалация

Статус показывает этап работы: обращение открыто, ожидает действий или завершено. Классификация описывает тему и причину обращения. Приоритет отражает важность, но может быть ограничен правилами проекта.

Меняйте эти поля только по фактам из переписки и контекста. `Эскалировать` означает передать ситуацию на более высокий уровень внимания. Это не замена обычной передаче другому оператору.

Часть действий может быть скрыта. Это нормально: право на чтение обращения не даёт право менять каждый статус или классификацию.

## SLA: сколько времени осталось

SLA — согласованный срок реакции или решения. В интерфейсе может быть несколько показателей, например время до первого ответа и время до решения.

`Под риском` означает прогноз сервера: при текущем ходе работы срок может быть нарушен. Это предупреждение, а не новый крайний срок. `Нарушен` означает, что договорной срок уже прошёл.

Оператор не меняет правила SLA в карточке обращения. Его задача — увидеть риск, проверить причину, ответить или передать обращение вовремя.

## Внешние задачи

Некоторые обращения связаны с задачами в JSM или HelpDesk. Вкладка интеграций показывает внешний статус, историю событий и доступные действия.

Внешняя задача помогает восстановить работу, но не заменяет обращение в Retenive. Не копируйте из неё закрытые данные в публичный ответ без разрешения.

Состояние `Результат неизвестен` означает, что команда могла выполниться, но подтверждение не пришло. Нажмите `Проверить результат`. Не создавайте новую внешнюю задачу для той же цели.

## Уведомления в браузере

В `Уведомления поддержки` подключается текущий браузер и выбираются типы личных уведомлений. Готовность состоит из трёх частей: разрешение сайта, подписка браузера и регистрация на сервере.

Устройство считается подключённым только после подтверждения сервера. Настройки относятся к выбранному проекту и текущему сотруднику. На общем компьютере отключите браузер перед выходом.

## Если экран пуст, данные устарели или доступ пропал

- Нажмите `Обновить`, если данные давно не менялись.
- Проверьте выбранный проект и активные фильтры.
- При сообщении о потере доступа вернитесь к очереди. Защищённые данные должны исчезнуть с экрана.
- При конфликте перечитайте данные и повторно подтвердите намерение.
- При неизвестном результате используйте только восстановление исходной попытки.
- После запроса новой аутентификации войдите снова. Старая команда не повторяется автоматически.

Не копируйте технический текст ошибки пользователю. Для обращения к лиду достаточно времени, названия раздела и понятного описания действия.

## Завершение смены

Перед уходом:

1. Проверьте обращения, где вы назначены или взяли работу на себя.
2. Завершите начатый ответ либо сохраните понятную внутреннюю заметку.
3. Передайте незавершённые обращения следующей смене.
4. Убедитесь, что нет неизвестного результата отправки или внешней команды.
5. Переключите доступность на `Офлайн`.
6. На общем устройстве отключите уведомления и выйдите из CMS.

Хорошая передача смены отвечает на три вопроса: что уже сделано, чего ждём и кто продолжает работу.

## Словарь оператора

| Термин | Что означает |
| --- | --- |
| Проект | Изолированная рабочая область со своими пользователями, очередями, материалами и правами |
| Пользователь | Человек, который обратился в поддержку |
| Обращение (Case) | Рабочая карточка со статусом, назначением, SLA и историей |
| Чат | Переписка с пользователем |
| Очередь | Набор обращений, ожидающих работы |
| Представление | Готовый или сохранённый набор фильтров |
| Назначение | Команда или сотрудник, отвечающий за обращение |
| Взял в работу | Сотрудник, который ведёт активную работу сейчас |
| Наблюдатель | Сотрудник, который следит за изменениями без владения обращением |
| SLA | Согласованный срок ответа или решения |
| Внутренняя заметка | Сообщение только для команды поддержки |
| Эскалация | Передача ситуации на более высокий уровень внимания |
| Внешняя задача | Связанная работа в JSM, HelpDesk или другой внешней системе |
| Неизвестный результат | Система пока не может доказать, выполнилась команда или нет |
