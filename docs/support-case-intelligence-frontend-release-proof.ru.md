# Case Intelligence — готовность фронта SP-34/35

## Что готово

- Постоянный экран: `/support/settings/case-intelligence/*`. Флагов, `VITE_*`,
  временного включения и второго старого редактора нет.
- Лид настраивает категории, точные правила, аудиторию, окна, контекст,
  ограничения и разрешённую сервером модель.
- Перед сохранением доступна адресная серверная проверка. Ошибка привязана к
  полю; необработанный текст сервера пользователю не показывается.
- Безопасная проверка принимает до восьми сообщений. Она не вызывает модель,
  не создаёт обращение и показывает решение, основание, кандидатов, доверие,
  стоимость и ход проверки.
- Экран калибровки показывает покрытие по решению, языку и каналу. Если данных
  мало, интерфейс не обещает автоматическое действие.
- Рабочее состояние берётся только из общей серверной версии. Отдельно
  опубликованные правила не называются уже применёнными.
- Обязательная защита платформы доступна проекту только для чтения и при
  согласовании закрывает обычные автоматические ответы безопасным резервом.

## Безопасность команд

- Доступ проверяется одновременно по точному праву и `allowedActions` сервера.
- Неопределённый результат записи хранит исходные тело, версию и ключ. Новая
  команда блокируется до проверки той же попытки.
- Смена пользователя, проекта или потеря нужного права очищает защищённые
  данные и запрещает повтор старой команды.
- `401/428` требуют нового входа; `403/404` закрывают экран без раскрытия
  серверных деталей.

## Проверенная матрица

- Desktop `1440×1000`, tablet `1024×768`, mobile `390×844`.
- Светлая и тёмная темы.
- Клавиатурная навигация, Back/Forward, отсутствие горизонтального
  переполнения, axe без отключения `color-contrast`.
- Полный путь: категория → правило → безопасная проверка → черновик →
  публикация; отдельно — лимиты и калибровка.

Снимки находятся в
`docs/evidence/support-workspace/ticket-35-case-intelligence/`.

## Проверки фронта

- `api:check`, typecheck, lint и architecture — пройдены.
- Проверки служебных скриптов — `62/62`.
- Vitest — `868` наборов, `2769/2769` тестов.
- Case Intelligence Playwright — `6/6` на desktop и mobile.
- Production build — пройден.

Общий Playwright всего репозитория на этом снимке не является зелёным:
`136` проверок прошли, `70` упали, `108` пропущены. Падения относятся к другим
экранам и старым тестовым данным — в частности, к AI-журналу, Сценариям,
Событиям, SLA и нескольким старым состояниям рабочего места. Они не возникли
из изменений SP-34/35, но до общего production GO владельцам этих областей
нужно восстановить полный browser gate.

## Условие production deploy

Фронт собран по составному контракту:

- актуальная серверная база — `4603a03944c6cec9751fd95eb8ce2133783fd07f`;
- Case Intelligence — `b26be183a6e1ab5c32c143ee6bab34c8fe16d00b`;
- OpenAPI — `sha256:89e5ca742adb3f39649fc893fc50109b098a77cfbbc343b67ebae48403e3f90e`.

Локальные SP-34/35 пока не входят в актуальный backend `origin/main`. До
выкладки владелец бэкенда должен объединить обе линии в один immutable commit,
исправить расхождение OpenAPI и compiler по `maxSignals`, верхним границам
окон attach/reopen и stable-code/scalar правилам, повторно экспортировать
OpenAPI и прогнать server + frontend gates. Фронт уже использует более строгие
фактические ограничения compiler. Без единого серверного кандидата и точной
схемы production GO не заявляется.
