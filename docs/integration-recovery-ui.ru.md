# Восстановление интеграций в CMS

Экран находится в настройках проекта, внутри отдельного модуля
`features/integration-recovery`. Он не меняет Events, Scenarios и обычную
обработку событий.

## Доступ

- `project.integration_activity.read` открывает безопасный список и детали
  операций. Payload, подписи, delivery key и секреты API не отображаются.
- Для `replay`, `cancel`, ручного `quarantine`, `pause` и `resume` одновременно нужны
  `project.integration_activity.read` и `project.integrations.manage`.
- Список подключений для direction pause/resume дополнительно виден только с
  `project.integrations.read`.
- Без полного набора прав интерфейс остаётся read-only и не показывает команды
  восстановления.

## Защита команд

Каждая команда требует причины и явного подтверждения. CMS отправляет новый
`Idempotency-Key`, ожидаемый статус и текущую operations/version проекцию.
Backend остаётся источником истины и отклоняет устаревшую команду конфликтом;
после любого результата CMS перечитывает список.

Ручной quarantine доступен только из деталей inbound-операции в состоянии
`RECEIVED` или `RETRY_WAIT`. Команда pin-ит `expectedStatus` и
`expectedOperationsVersion`; terminal operation, операция без прав или уже
изменённая операция не получает кнопку либо отклоняется backend. Результат
запроса старого Project после переключения не отображается в новом Project.

Для повторной отправки со статусом `OUTCOME_UNKNOWN` есть отдельное
подтверждение риска дубликата. Пауза применяется независимо к входящему и
исходящему направлениям конкретного подключения.

Операции `CONNECTION` показываются отдельным типом «Подключение», а не как
отправка. В деталях у них нет фиктивного route; направление и история pause/resume
отображаются понятными операторскими названиями.

Список намеренно ограничен последними 50 операциями. Фильтры, пагинация и
ручной remap не входят в минимальный recovery UI и могут быть добавлены в этот
модуль без изменения страниц Events и Scenarios.
