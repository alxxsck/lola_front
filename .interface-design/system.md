# UI-система Lola CMS

## Support Workspace: направление

- **Кто работает:** оператор поддержки или lead, который долго находится в очереди,
  читает диалог и принимает частые операционные решения под нагрузкой.
- **Главная задача:** быстро понять, кто отвечает за Case, и безопасно взять,
  передать или вернуть работу, не теряя контекст разговора.
- **Ощущение:** плотное, спокойное и технически надёжное рабочее место. Интерфейс
  не должен выглядеть как набор декоративных карточек или отвлекать от ленты сообщений.
- **Домен:** очередь, Case, назначение, claimant, наблюдатели, доступность,
  routing offer, SLA, конфликт версий, audit trail.
- **Цветовой мир:** нейтральный canvas, белая/системная рабочая поверхность,
  приглушённые разделители, фирменный синий для разрешённого действия,
  мягкий brand tint для текущей ответственности, системные warning/danger только
  для настоящего риска. Использовать существующие semantic tokens, а не raw hex.
- **Фирменный паттерн:** `Responsibility rail` — четыре независимые строки
  «Назначение / Claimant / Наблюдатели / Доступность», дополненные временным
  глобальным offer tray над рабочей областью.
- **Не использовать:** одинаковые карточки для каждого значения; смешивание
  владельца Case с claimant или presence; постоянные яркие баннеры; отображение
  opaque ID, ETag, version или offer token в операторском UI.

## Основа композиции

- Базовая сетка отступов — **4px**. Основные значения: `8 / 12 / 16px`.
- Плотность — workbench-tight: важные статусы помещаются в одну компактную панель,
  а чтение диалога остаётся главным фокусом экрана.
- Стратегия глубины — **тихие borders + tonal surface shifts**. Не добавлять
  декоративные тени к внутренним панелям Support Workspace.
- Граница панели: `1px` через `var(--line)` с пониженной интенсивностью.
- Радиус рабочих панелей — **14px**. Радиус и компоненты PrimeVue должны оставаться
  согласованными с текущей CMS-темой.
- Акцент расходуется только на основное разрешённое действие, выбранный объект и
  актуальный routing offer. Вторичные действия — `secondary/outlined` или `text`.

## Иерархия текста

- Section kicker: около `0.72rem`, muted, повышенная насыщенность/трекинг из общей темы.
- Заголовок внутренней панели: `0.94rem / 750`, `letter-spacing: -0.01em`.
- Значение статуса: `0.8rem / 650`, primary text, `line-height: 1.35`.
- Label и metadata: `0.72rem / 700` и muted; supporting copy — `0.72–0.86rem`.
- Иерархию строить весом и цветом раньше, чем увеличением размера.
- Динамические сроки и счётчики должны быть стабильными по ширине; при появлении
  числовых таблиц использовать tabular numerals.

## Responsibility rail

Переиспользовать для Case ownership и связанных, но независимых состояний.

- Контейнер: grid, `14px` radius, overflow hidden, тихая `1px` граница.
- Строка desktop: `min-height: 48px`, `padding: 9px 12px`, `gap: 12px`.
- Колонки desktop: `minmax(108px, 0.8fr) minmax(0, 1.2fr)`.
- Label: иконка `14px`, gap `8px`, muted. Значение переносится через
  `overflow-wrap: anywhere`, а не обрезается.
- Первая строка «Назначение» получает мягкий `brand-soft` tint; остальные строки
  остаются нейтральными, потому что это контекст, а не четыре равных CTA.
- Не подменять неизвестное состояние выдуманным владельцем. Использовать
  «Обновляем…», «Не загружено» или другой честный neutral state.
- На ширине до `560px` переходить в одну колонку с `3px` gap между label и value.

## Действия назначения

- Порядок: primary «Взять в работу»; secondary outlined «Передать»; danger outlined
  «Снять». Показывать только действия, разрешённые effective permission и текущим
  server-owned action snapshot.
- Группа действий: flex-wrap, `8px` gap. Минимальная высота любой кнопки — **44px**.
- На mobile кнопки занимают всю ширину, без горизонтальной прокрутки.
- Во время mutation или unknown outcome нельзя разрешать другое конкурирующее действие.
- Повтор неизвестного результата явно называется «Повторить тот же запрос» и доступен
  только пока совпадают Project, Case version, assignment version/ETag, capability,
  Team/operator action и срок offer. Технические токены пользователю не показывать.
- При `409` диалог и введённый оператором draft остаются на месте, а данные
  сверяются с сервером. При revoke/смене Case action surface закрывается и очищается.

## Диалоги claim / release / transfer

- Использовать PrimeVue `Dialog`, `Button`, `Select`, `Textarea`, `Message`, сохраняя
  keyboard/focus/ARIA-поведение библиотеки.
- Ширина: claim `min(430px, 100vw - 32px)`; release `460px`; transfer `520px`.
- Lead copy: `0.86rem`, muted, `line-height: 1.5`, нижний отступ `16px`.
- Поле: grid, `7px` gap, верхний отступ `14px`, label `0.84rem / 700`.
- Supporting text и счётчик: `0.74rem / 500`, muted.
- Transfer Team + operator: две равные колонки с `12px` gap; до `560px` — одна колонка.
- Причина обязательна для release/transfer; комментарий до 500 символов явно помечается
  как необязательный и сохраняется при version conflict.

## Routing offer tray

- Это глобальная, временная и персональная поверхность; она не зависит от выбранного Case.
- Desktop grid: `auto minmax(0, 1fr) auto`, `14px` gap, `10px 12px` padding,
  `14px` radius, тихая brand border и мягкий brand surface tint.
- Signature marker: точка `8px` с негромким `4px` halo. Не анимировать постоянно.
- Список ограничен `112px` по высоте и скроллится внутри с
  `overscroll-behavior: contain`.
- Срок предложения имеет больший вес, чем supporting copy. По истечении строка и
  возможность replay удаляются автоматически, без клика оператора.
- До `700px` список переносится на всю ширину, offer actions делят строку поровну,
  каждая кнопка не ниже `44px`.
- Empty state не резервирует высоту рабочего места.

## Адаптив и проверка

- Desktop сохраняет три рабочих области; mobile использует route stack и показывает
  одну задачу за раз, без попытки сжать desktop shell.
- Ни панель, ни диалог, ни action group не должны создавать горизонтальный overflow.
- Первичная загрузка страницы использует один page-level readiness gate: не показывать
  независимые секционные скелетоны по мере завершения отдельных запросов.
- Полностраничный skeleton повторяет реальную responsive-сетку, порядок и базовую
  геометрию всех основных блоков. Каркас меняется на готовый контент только после
  завершения всех обязательных стартовых проекций.
- После первой загрузки refresh сохраняет последнюю подтверждённую проекцию на месте;
  состояние обновления показывается локально и не возвращает готовую секцию в skeleton.
- Skeleton и контент меняются общим crossfade/translate не дольше 180–220 ms без
  изменения layout flow; при `prefers-reduced-motion` остаётся только короткий opacity.
- Для каждого нового состояния проверять desktop и mobile, loading/empty/error,
  permission revoke, `409`, unknown outcome, expiry и keyboard focus.
- Эталонные снимки пункта 17:
  `docs/evidence/support-workspace/ticket-17-assignment-desktop.png` и
  `docs/evidence/support-workspace/ticket-17-assignment-mobile.png`.
- Эталонные компоненты:

## Shared composer: public reply / internal note

- Это одна Conversation Surface и один composer. Не создавать отдельный note-editor
  рядом с публичным ответом и не переносить заметку в модальный workflow.
- Переключатель режима расположен первым элементом composer. Оба состояния имеют
  текст, иконку и `aria-pressed`; цвет не является единственным различием.
- Public reply остаётся нейтральным. Internal note получает спокойный warning-tint,
  lock/shield и постоянную подпись «Видно только команде».
- Draft key включает `Project + actor + Conversation + mode`. Текст, перевод,
  вложения и send-attempt никогда не переходят между режимами.
- В note-режиме над composer появляется компактная «Закрытая лента»: максимум две
  записи на desktop и одна на mobile. Полная история, correction и tombstone
  открываются отдельной кнопкой, не раздувая основную переписку.
- CTA называется «Добавить заметку»; public CTA — «Отправить». Note mode не показывает
  recipient presence, translation, templates или AI improve.
- Revoke или переход capability `create/read` в false немедленно очищает note draft,
  закрытую ленту, подробную историю и возвращает безопасный public mode.
- Анимация раскрытия ленты — 180 ms opacity/translate/max-height; при
  `prefers-reduced-motion` отключается. Touch targets на mobile — не меньше 40–44px.

## Conversation presence

- В плотном заголовке presence показывается как компактная кнопка `eye + count`,
  а не как постоянно растущая строка имён.
- По клику открывается PrimeVue Popover со всем актуальным списком viewers;
  одна и та же модель работает для одного и нескольких операторов.
- Popover всегда поясняет, что просмотр не означает назначение Case. Presence,
  claimant и assignment визуально и семантически не смешиваются.
- Кнопка имеет минимум 44px по ширине, tabular count, keyboard focus и доступное
  имя; popover помещается в mobile viewport и поднимается выше full-tab shell.

## Conversation Surface: короткий desktop viewport

- На desktop-окнах высотой до 760px переписка остаётся главным рабочим объектом:
  message log занимает не меньше 30% высоты Surface и не меньше 160px.
- Toolbar не складывается в три вертикальных ряда из-за узкой центральной колонки:
  заголовок, компактный presence и переключатель перевода остаются в одной строке.
- Внутренняя «Закрытая лента» становится однострочным rail и показывает одну
  последнюю заметку; полный список остаётся доступен по кнопке «Все заметки».
- Composer уплотняет только вертикальные интервалы и высоту textarea. Режим,
  privacy-пояснение, byte counter и обе основные кнопки остаются видимыми.
- Mobile сохраняет собственную touch-компоновку с целями 40–44px; desktop density
  rule не должен переопределять mobile media query.

## Inspector: Пользователь и Профиль

- «Пользователь» — безопасная операционная сводка: identity, активность, язык и
  контекст текущего диалога. Факты отображаются спокойным списком label/value,
  без сетки одинаковых mini-cards.
- «Профиль» — отдельная permission-gated Product Profile projection. Она
  загружается лениво и показывает project fields, freshness, provenance,
  classification и запланированные AI Memory blocks.
- Пользовательская подпись «Данные» для вкладки `DATA` не используется: она не
  объясняет границу доступа и визуально дублирует «Пользователь».

## Маршрутизация: правила назначения

- Пользовательский термин — **«Правило назначения»**. «Политика» остаётся только
  техническим именем серверного ресурса и не показывается в интерфейсе. Правило
  объясняется как последовательность: отобрать подходящих операторов, определить
  порядок обращений, выбрать исполнителя и повторить попытку при неудаче.
- Страница использует полноширинный каталог, а не постоянную боковую колонку с
  редактором. Вверху расположен причинный rail из трёх шагов; ниже каждое правило
  занимает отдельную строку и показывает состояние, число связанных очередей,
  предел занятости и число попыток.
- Карточка правила: `16px` padding, `12px` radius, тихая `1px` граница, `14–18px`
  gaps. Факты собираются в tonal rail из трёх колонок; действия выравниваются
  вправо. На mobile факты и действия переходят в одну колонку без горизонтального
  overflow.
- Создание и редактирование выполняются в одном PrimeVue `Dialog` шириной
  `min(68rem, 100vw - 32px)`. Редактор строится как последовательность пронумерованных
  секций: идентификатор при создании, допустимость оператора, порядок обращений,
  оценка оператора, неудачное назначение. Footer остаётся доступным при внутреннем
  scroll.
- Секция редактора: grid `30px minmax(0, 1fr)`, `12px` gap, `16px` padding,
  `13px` radius и `surface-subtle`. На ширине до `760px` секция становится
  одноколоночной с `13px` padding.
- Каждое поле получает `FormFieldLabel` с доступной подсказкой `i`. Название поля
  говорит о пользовательском результате, а не о серверном ключе: «Время на ответ
  оператора», «Пауза перед новой попыткой», «Максимальная занятость оператора».
  Для весов дополнительно показывается одно короткое предложение о направлении
  влияния; сумма весов не представляется процентом и не обязана равняться 100.
- Строка веса: `min-height: 62px`, `10px 12px` padding, описание слева и числовое
  поле `132px` справа. На mobile поле переносится под описание. Числа используют
  tabular numerals, значения всех общих `InputText`, `InputNumber`, `Select` и
  `MultiSelect` — `font-weight: 400`.
- Идентификатор называется служебным именем, сопровождается примером с дефисом и
  пояснением неизменяемости. Нижнее подчёркивание преобразуется в дефис до отправки;
  ошибка формата показывается рядом с полем.
- Ошибка действия принадлежит поверхности, где оно началось: создание, сохранение
  и применение показывают ошибку внутри диалога. Page-level Message остаётся только
  для загрузки и действий самой страницы.
- Кнопки редактора: secondary text «Закрыть», secondary outlined «Сохранить» и
  primary «Сохранить и применить». Слово «черновик» не используется как основное
  действие; состояние формулируется как «Пока не применяется» или «Есть изменения,
  которые ещё не применены».
